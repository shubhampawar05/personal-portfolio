Never let the LLM write URLs

My persona chatbot kept sharing YouTube links that looked real and weren't. Here's the pattern that fixed it: let the model choose, and let code fill in the facts.

ChaiCode Mentors is a chat app with two AI personas, modelled on the public teaching style of two coding educators. Ask a question and the mentor answers in short, spoken-style Hinglish — and when it helps, shares a video from their own YouTube channel.

That last part was the hard bit. The first version had a simple problem: the links were made up.

The problem: plausible but fake links

If you ask an LLM to "share a relevant video", it will produce something that looks exactly like a YouTube link. Sometimes the video ID is invented. Sometimes it's a real video copied with one character wrong. Sometimes it's a real video from a different channel. All of them look fine until a user clicks.

Prompting harder ("only share real links!") didn't fix it. The model doesn't know which links are real — it only knows what links look like.

Step 1: give the model a tool

Instead of asking the model to remember videos, I gave it a searchYouTube tool that searches only that mentor's channels. The server runs the search with the YouTube Data API, drops deleted or private videos, and returns the results to the model.

Tool calling is a loop. The model can answer, or ask for a tool. If it asks, the server runs the tool, adds the result to the conversation, and calls the model again:

for (let round = 0; round < 3; round++) {
  const reply = await callModel(messages, tools);
  if (!reply.toolCalls.length) return reply;   // final answer
  for (const call of reply.toolCalls) {
    messages.push({ role: 'tool', tool_call_id: call.id, content: await runTool(call) });
  }
}
throw new Error('The model kept calling tools without answering.');

Two things I learned here. Always cap the rounds — a model can keep calling tools forever. And if anything fails, roll the conversation history back to where it was, so a half-finished tool call doesn't corrupt the next message.

Step 2: never give the model the URL

Even with real search results, the model could still copy a URL wrong. So the tool result doesn't contain URLs at all. Each video gets a placeholder ref, and the model only sees titles:

{ ref: "VIDEO_1", title: "Complete Git and GitHub course" }
note: "To share a video, write its ref exactly, e.g. {{VIDEO_1}}.
       It becomes the real link automatically. Never write a URL yourself."

The server keeps a map from VIDEO_1 to the real video. When the answer comes back, it swaps {{VIDEO_1}} for a video card with the verified link and thumbnail. If the model writes a ref that doesn't exist — or types a YouTube URL anyway — the server replaces it with a card for the mentor's channel. The UI can never show a broken link.

The general lesson: let the model choose, let code produce the facts. The model is great at deciding which video fits the question. It's bad at reproducing an 11-character ID exactly. So it picks, and the server fills in.

The streaming bug that came with it

Replies stream to the browser word by word. That broke the placeholders in a way I didn't expect: tokens don't respect my syntax, so a ref can arrive split in two —

chunk 1: "Yeh video dekho {{VID"
chunk 2: "EO_1}} — isme sab hai"

If I forward chunk 1 straight away, the user briefly sees {{VID on screen. The fix is to hold back anything after an unclosed {{ until the closing }} arrives, then send it with the ref already swapped. When the stream ends, the server sends the final cleaned text, and the browser replaces what it streamed with that — so the final render is always the source of truth.

What else I'd keep from this project

  • A persona lives in the system prompt. The voices only felt distinct after I researched each mentor's public talks and posts and wrote down their actual phrases and habits.
  • Public AI apps need rate limits. Every message costs money, so each visitor gets a per-minute and per-day limit.
  • Say clearly what it is. The app states that these are AI simulations built from public content, not the real people.
