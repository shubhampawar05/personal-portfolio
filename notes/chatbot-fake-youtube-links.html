My chatbot kept making up YouTube links

I built a chatbot with two coding-mentor personas that suggests YouTube videos. The first version gave links that looked real but weren't.

ChaiCode Mentors was an assignment in the GenAI cohort I was doing. It's a chat app with two personas based on the public teaching style of Hitesh Choudhary and Piyush Garg. You ask about code or your career, you get a short reply in Hinglish, and when it makes sense, a video from their own YouTube channel.

The video part is where I got stuck.

The links were fake

In the first version I simply asked the model to share a relevant video. It always gave a link, and the links looked perfect. But some of the video IDs didn't exist, some were real videos with one wrong character, and some were from a completely different channel. You only find out when you click.

Adding "only share real links" to the prompt didn't help at all. The model has no way of knowing which links are real. It only knows what a YouTube link looks like.

Giving it a search tool

So I gave the model a searchYouTube tool that only searches that mentor's own channels. The server calls the YouTube Data API, removes deleted or private videos, and sends the results back to the model.

Tool calling works as a loop. The model either answers, or asks for a tool. If it asks, the server runs the tool, adds the result to the chat, and calls the model again:

for (let round = 0; round < 3; round++) {
  const reply = await callModel(messages, tools);
  if (!reply.toolCalls.length) return reply;   // got the final answer
  for (const call of reply.toolCalls) {
    messages.push({ role: 'tool', tool_call_id: call.id, content: await runTool(call) });
  }
}
throw new Error('The model kept calling tools without answering.');

Two things I learned while building this. First, put a limit on the rounds, otherwise the model can keep calling tools and never answer. Second, if anything fails halfway, reset the chat history to what it was before that message. Otherwise a half-finished tool call stays in the history and breaks the next reply.

Not giving it the URL at all

Search fixed the made-up videos, but the model could still copy a URL wrong. So I stopped sending it URLs. The tool result only has the titles and a short ref for each video:

{ ref: "VIDEO_1", title: "Complete Git and GitHub course" }
note: "To share a video, write its ref exactly, e.g. {{VIDEO_1}}.
       It becomes the real link automatically. Never write a URL yourself."

The server keeps a map from VIDEO_1 to the real video. When the reply comes back, it replaces {{VIDEO_1}} with a video card that has the real link and thumbnail. If the model writes a ref that doesn't exist, or types a YouTube URL anyway, that gets replaced with a link to the mentor's channel. So the UI never shows a broken link.

The way I think about it now: the model is good at picking which video fits the question. It's not good at copying an 11 character ID perfectly. So it picks, and my code fills in the actual link.

Then streaming broke it

Replies stream to the browser word by word. The problem is that tokens don't care about my {{ }} format, so a ref can arrive in two pieces:

chunk 1: "Yeh video dekho {{VID"
chunk 2: "EO_1}}, isme sab hai"

If I send the first chunk straight to the browser, the user sees {{VID on the screen for a moment. The fix was to hold back any text after an unclosed {{ until the }} arrives, and then send it with the ref already replaced. At the end the server also sends the final cleaned-up text and the browser swaps it in, so anything odd in the streamed version gets corrected anyway.

A few other things

  • The two personas only started sounding different after I went through their public videos and posts and noted down phrases they actually use. A generic "talk like a friendly teacher" prompt made both of them sound the same.
  • Every message costs money, so each visitor gets a per-minute and per-day limit.
  • The app clearly says these are AI simulations and not the real people. Since they're real people, that felt important.
